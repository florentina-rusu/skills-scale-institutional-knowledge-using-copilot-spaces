# OctoAcme Project Management Docs

This folder contains OctoAcme’s project management process guides. Projects follow a lightweight lifecycle: initiate work by validating the business need, outcomes, stakeholders, and initial risks; plan scope, backlog, dependencies, responsibilities, and milestones; execute and track delivery; release and verify changes; then capture learning through retrospectives and continuous improvement.

The process is supported by clear roles. The Project Manager (PM) coordinates delivery, schedules, risks, and communications, while the Product Manager (PdM) defines outcomes, prioritizes work, and measures success. Developers build and test increments, QA/testing validates quality and acceptance criteria, and stakeholders provide input and approvals. Teams track work on a project board and use regular standups, delivery and PM–PdM syncs, demos, stakeholder updates, and escalation paths to maintain alignment and resolve blockers.

Quality is integrated throughout delivery: teams define acceptance criteria and a Definition of Done, run unit and applicable integration tests, and use end-to-end smoke tests for critical flows. CI should run tests, linting, and security scans; manual QA is used where needed. Releases require acceptance criteria to be met, release notes, a rollback or mitigation plan, and staging and post-deployment checks. Retrospectives turn lessons into owned, time-bound improvement actions.
